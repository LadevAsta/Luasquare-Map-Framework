DFR VMF integration notes

Purpose:
    This file records the Lua calls expected by the current DFR machinery/control architecture.
    It is for gm_darkfusion_v2 VMF/bootstrap testing, not final player-facing documentation.

Bootstrap calls:
    include('luasquare_dfr/init.lua')

    -- Optional but recommended for testing the current gm_darkfusion_v2 armature targetnames.
    DFR.RegisterDefaultReactorMachineLayout()
    DFR.RegisterDefaultCoreVisuals()

    -- Existing control and telemetry registration can remain map-owned.
    DFR.Start()

Path track callbacks:
    Each important path_track should call Lua when a train passes it.

    Preferred call:
        DFR.OnPathTrackPassed('dfr_pt_upper_1')

    Aliases:
        DFR.PathTrackPassed('dfr_pt_upper_1')
        DFR.TrackPassed('dfr_pt_upper_1')

    If two logical trains ever share a node name, pass the machine id:
        DFR.OnPathTrackPassed('dfr_pt_upper_1', 'upper_shaft_train')

Path track branching:
    The stabilizer path uses dfr_pt_stab_2 as a branch switch.
    When Lua routes the stabilizer train from dfr_pt_stab_1 toward dfr_pt_stab_3, it fires:
        dfr_pt_stab_2 -> EnableAlternatePath

    For routes that should use the default dfr_pt_stab_2 -> dfr_pt_stab_1 path, Lua fires:
        dfr_pt_stab_2 -> DisableAlternatePath

    Lua also disables the alternate path again after the destination path_track is reached.

3D2D display auto dimensions:
    The 3D2D module now reads targetnames shaped like:
        DISPLAY34x19_dfr_status_panel
        DISPLAY512x256_dfr_status_panel

    The numbers are always Hammer-unit panel dimensions.
    DISPLAY512x256_ means a 512x256 Hammer-unit surface.
    Canvas size is derived from scale, so the default 0.1 scale makes that a 5120x2560 canvas.
    Explicit bootstrap dimensions or scale fields still override/refine the targetname metadata.

Binding display metadata:
    DFR bindings can now carry map-owned display metadata.
    This keeps the targetname and display tuning together in the bootstrapper:

        DFR.RegisterBinding('core_status_panel', {
            targetName = 'DISPLAY512x256_dfr_status_panel',
            class = 'info_target',
            required = false,
            display = {
                scale = 0.2,
                title = 'DFR CORE STATUS',
                surfaceOffset = 0.05
            }
        })

    DFR.RegisterDefaultTelemetryDisplays() will use binding.display as its default data.
    Explicit options passed directly to RegisterDefaultTelemetryDisplays still override the binding metadata.

3D2D surface offset:
    3D2D displays default to a tiny normal offset of 0.05 Hammer units to reduce Z-fighting
    when the info_target sits exactly on a brush face.

    The offset is applied along the display plane normal, which is the target's local Z/blue axis.
    Set it per display when needed:

        display = {
            scale = 0.2,
            surfaceOffset = 0.1
        }

    Set surfaceOffset = 0 to disable it.
    Accepted aliases are normalOffset, planeOffset, zFightOffset, zFightingOffset, and depthOffset.
