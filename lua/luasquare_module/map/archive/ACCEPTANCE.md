# Archived Garry's Mod acceptance: migration 01–30

Status: the `experiment_rbmk` reference acceptance cycle passed after five remediation rounds. The in-game runs are preserved in [ACCEPTANCETESTS.md](ACCEPTANCETESTS.md). Multiplayer late-join test 19 and multi-core fixture tests 20–24 were explicitly deferred because their required environment, graph-editor capability and target debug draw were unavailable; they remain future validation rather than completed coverage. The procedure below is retained as the historical test definition.

## Normal reference manifest

1. **Fresh activation.** In the server console, set `luasquare_map_manifest ""` after the convar exists, then `changelevel experiment_rbmk`. Initial loading of the map creates the convar if needed. Expect exactly one `Activated experiment_rbmk from experiment_rbmk/main.json` message and no `Plant inactive` diagnostics. Inspect `LUASQUARE_MAP.Instances.experiment_rbmk` and `LUASQUARE_RBMK.Get('reference')` in a trusted server Lua console if necessary. There must be one reference core, not fixture cores. No draft file should affect startup.
2. **Initial state and cadence.** Open `luasquare_map_editor`, open Sources, select `experiment_rbmk/main.json` in Packed manifests and press **Load selected packed manifest**. Inspect `reference`, its separator, deaerator, grids and pumps. Check initial inventories/capacities against the packed files and captured baseline. Feedwater target must initialize to 80 for both feedwater pumps. Observe stable core/plant 0.1 s ticks, SEG7 0.1 s, gauges/displays 0.2 s and annunciators 0.5 s. Leave the plant idle and check for duplicate updates, console errors or unexplained inventory jumps.
3. **Physical controls and locks.** Use the actual control-room buttons, safety covers and toggles. Each press must produce one attributed action. Repeat through the Control editor's packed LIVE controls. Check PressLock/InLock/OutLock, existing owner locks, momentary returns, delayed acknowledgement, two-second expiry and five-second movement timeout using the [Control acceptance procedure](../../control/README.md). A blocked control must remain blocked for player, NPC and automated requests.
4. **Keypads and paired targets.** Exercise digits 0–9, submit, clear/backspace where present, overflow/limits and empty-zero submission on `fwlevelctrl`, `hotwellctrl`, `aprctrl` and `rodctrl`. Check the physical SEG7 skins. Set `fwlevelctrl` to 70 and inspect both `reference.feedwater_pump_a` and `_b`; both targets must become 70. Change hotwell target independently. Rejected rod submission with no selection must not move any rod, set a persistent Control fault or prevent the next valid submission.
5. **Feedwater and circulation.** Start/stop both feedwater and main-circulation pumps using their speed buttons and OFF buttons. Inspect power demand, accepted power and actual flow while changing speed. Observe separator/core inventory transfer and level regulation. Close water isolation and reopen it; verify accepted-transfer accounting, no invented water, and normal recovery. Operate `valve_recirc_drain_valve` and `valve_hotwell_drain_valve`; only their declared networks should drain.
6. **Power loss and restoration.** Open `electrical_transformer_startup_station_transformer` and appropriate station/generator supply paths to remove plant power. Pumps and powered rods must respond to the actual grid/breaker state; control-room UPS behavior must match its inventory. Restore supply and use `button_stationgrid_resettrip` / `button_generatorgrid_resettrip` where tripped. Confirm no hidden legacy grid remains supplying loads. In plant debug, inspect `NET reference.hotwell`: `OVF` and other endpoint fields must use readable `component/port` labels and never print `table: 0x...`.
7. **Cooling and condensate.** Operate condensate and circulating-water speed controls, cooling-water and hotwell makeup toggles. Observe condenser condensation, hotwell return, cooling-tower basin temperature/level and makeup consumption. Confirm gauges and status panels track their corresponding instances. Check the deaerator steam/relief controls, automatic regulation and overflow toggle without unconnected-network errors.
8. **Turbine and generator.** With steam available, increase/decrease `turbine_valve_tg1_*` and bypass controls at each step size. Compare RPM, pressure, vibration, power and extraction/condensation behavior with the existing operator workflow. Exercise `button_tg1_sync`, auto-sync, trip, reset and repair with their safety covers. A valid sync-button press is always consumed: while tripped it has no reaction; while synchronized it opens the breaker; while unsynchronized it attempts synchronization and closes on success. A mismatch may still trip the configured turbine/generator, but must not reject or restore the momentary button. Confirm grid export through declared transformers. Check turbine loop audio volume/pitch and shake response; trip/cleanup must stop persistent effects.
9. **Diesel behavior.** Operate `electrical_diesel_edg1`, observe generator ramping and fuel draw/refill on the electrical panel. In a disposable session, reduce the explicitly addressed diesel tank/fuel supply through trusted debugging, verify exhaustion stops generation, then restore fuel and confirm restart. No other generator or fuel inventory should change without its declared network interaction.
10. **Rod selection and motion.** Toggle individual U/R rods, yellow/red groups and clear selection. Only declared selector sprites should change. Submit 0, 50 and 100 through `rodctrl`; verify insertion inversion, motion limits, rod power demand and loss-of-power behavior. Change neutron source `(3,5)` and reflector `(5,2)` independently. Check stuck-rod/SCRAM behavior in a separate failure session.
11. **APR and SCRAM.** Set a positive target using `aprctrl`, observe automatic regulation and insertion limits, then enter zero to disable. Trigger `button_scram` through its safety cover and verify rods insert, APR responds as before, and a critical attributed event is logged. Reload before destructive tests. Test the extreme turbine trip and core failure effects only in disposable sessions; verify the intended relays/valves and no orphan effects afterward.
12. **Presentation.** Compare all physical gauges, numeric displays, pump/electrical/deaerator/turbine/RPV panels and graphs with the inspected component state. Check level, pressure, heat, xenon and flow values, units and unavailable-value behavior. Use `alarm_test`, acknowledge, mute and reset; verify visual latching/clearing and alarm audio. There must be no missing `rbmk.*` provider errors; providers now use `reference.*` IDs.
13. **Debug views.** Enable RBMK debug from Options → Luasquare with core ID `reference`. Verify cell positions at the packed physical anchor, fuel/flux/rod/pressure data and distance/FOV filters. Disable the view and check networking quiets. Check plant overlays and monitor positions. Debug state must not become an operator input.
14. **Editor workflow.** Open the plant editor from Options → Luasquare → Powerplant Framework. Move, resize, minimize, maximize and restore it, resize the graph/inspector splitter, and hover source/catalog/cell windows while the main window is in front. Open Sources: search and explicitly load a packed manifest, then use the Local drafts file browser and its tooltips without typing a path. Confirm export warns before overwriting, and that Manifest/startup settings are beside Sources in the main toolbar. The source manager must not contain buttons for other editors. Search components and types; inspect Source bindings, machinery/path fields, gauges, SEG7 and selectors. Check labels, family border colors, generated owners, typed ports and state in the cursor-side hover card. Verify readable dark controls and in-window diagnostics at smaller window sizes.
15. **Structural editing.** In a draft, right-click empty space and add a component and a preset at the clicked graph coordinate. Right-click a node, choose Start connection and a supported category/port, verify the submenu opens and only compatible destinations highlight, then connect across two packs. Click empty space during a second connection to cancel. Reject incompatible units/directions and over-capacity ports. Switch among All, Fluid, Electrical and References views; confirm arrowheads terminate visibly at whichever node border the route reaches and two offset lanes represent bidirectional links. Pan by right-dragging without opening a menu, zoom, click a node without moving it, then drag it and observe the live preview before its snapped 16-unit position commits. Select a node and confirm all touching links highlight. Click any visible segment of an authored link, confirm it highlights and exposes one anchor, drag that anchor, then move a connected node and confirm the anchor follows. Reload the draft to confirm editor-only route persistence. Group and duplicate linked components, then undo/redo. Verify internal references remap and external references remain explicit. Add a powered pump without a breaker and a diesel without a generator; inspect the generated ownership explanation, move the generated nodes independently, and configure runtime settings through their owner or explicit overrides. Delete/unlink and verify dangling references produce diagnostics. Edit a core cell kind/fuel/rod property, intentionally make it invalid, then repair it without reloading the document. None of these operations may actuate entities or change live inventories.
16. **Export and promotion.** Export a draft, select it through Sources → Local drafts, press **Load selected local draft**, and compare canonical contents and explicit overrides. Empty arrays must remain empty arrays. Export again and confirm overwrite requires an explicit choice. Packed files must remain unchanged. Manually copy reviewed draft files to their matching `data_static/luasquare/{map,components}/` paths in a test addon, select that manifest and reload the map. Confirm the changed plant activates only after reload. Restore the normal manifest afterward.
17. **Cleanup and ownership.** While pumps, turbine audio and a timeline/Control request are active, use Clean Up Everything. Verify dependent runs/audio/effects stop, bindings are reconstructed, counters/inventories return to initial state, no stale inspection/preview remains and the plant activates once. Repeat twice, then changelevel and repeat. Close editors with an active subscription and disconnect an inspecting admin; server subscriptions must disappear.
18. **Failed startup.** Copy a fixture to new test paths (do not damage the reference). Try duplicate IDs, a missing binding, a wrong-class target, bad endpoint/unit, unknown fuel and an invalid selected Control/timeline source. Reload with each manifest. Expect actionable source/component diagnostics, inactive map state, no partial pump/core timers, no registered stale actions/endpoints and no surviving effects. Correct the source and reload; activation should recover. Drafts alone must never affect this test.
19. **Late join and authority.** With the reference running, join with a new admin and then a non-admin client. The admin's catalog and selected telemetry should initialize without restarting the plant. Displays, alarm states, audio and selected core debug should initialize appropriately. Non-admin catalog/source/inspection requests must be rejected on multiplayer. Repeated selection changes must remain bounded and not freeze the client. Reload/cleanup should close/reset inspection state.

## Two independent cores

20. **Activate explicitly.** Set the server convar `luasquare_map_manifest "_fixtures/two_core.json"`, then `changelevel experiment_rbmk`. The normal physical operator sources are intentionally absent. Expect `fixture.alpha` and `fixture.beta`, distinct grids, rod breakers, steam networks, supply boundaries and feed pumps. They have no physical failure relays or rod sprites. They must never load during normal startup.
21. **Virtual operator isolation.** Open the Control editor's packed LIVE controls and select `fixture.alpha.select`, then `fixture.alpha.rods_out` / `.rods_in`. Check only alpha's R1 target changes. Repeat `.apr_on`, `.apr_off`, `.feed_on`, `.feed_off` and `.scram`. Compare beta's rods, selection, APR, water/steam, failure state and telemetry before/after; natural independent simulation may continue, but no alpha command may mutate beta. Repeat in reverse. Use `luasquare_rbmk_debug_core fixture.alpha` and `fixture.beta` to address each debug view explicitly.
22. **Destruction and effects.** In a disposable server-console session, run `lua_run LUASQUARE_RBMK.Get('fixture.alpha').Destroy()`. Alpha endpoints/timers must disappear, alpha actions must report unavailable, and beta must continue with its own state and timers. Trigger alpha failure before destruction in a separate session if testing failure cleanup. Because the fixture deliberately has no shared Source effects, no reference-map valve/sprite/relay should fire. Cleanup/reload must recreate both cores cleanly.
23. **Intentional interaction.** Make a separate draft of the two-core fixture. Add a `plant.valve` with `a:{component:"fixture.alpha",port:"water"}`, `b:{component:"fixture.beta",port:"water"}` and valid rate/open configuration using the structured inspector. Start with different levels, manually promote and reload. Only this declared connection should transfer water; total accepted inventory should be conserved. Close the valve through a declared virtual Control action and verify the interaction stops. The automated endpoint test separately checks rejection/rollback when a target cannot accept flow.
24. **Heat-exchanger example.** Select `_fixtures/heat_exchanger.json` and reload. Inspect `hx.hot`, `hx.cold`, their pumps and `hx.exchanger`. Hot temperature should fall, cold temperature rise and heat transfer remain bounded by approach/effectiveness/thermal limits. No core or normal reference controls should start. Reset the convar to `""` and reload to return to normal operation.

## Hammer / BSP handoff

The existing `experiment_rbmk.vmf` and BSP entity lump were read-only audited. Current operator `RunPassedCode` outputs already route through `LUASQUARE_CONTROL.ReportOutput`; no additional legacy bridge or Hammer edit is required for normal startup or either fixture. Keep the existing bootstrap `lua_run` and **Run Code on Spawn** enabled.

SEG7 renaming is optional for the current reference map because its explicit `digits` arrays remain supported. For a new or manually converted display, rename only its `prop_dynamic` digit entities to `SEG7_<display>_0`, `SEG7_<display>_1`, and so on with no gaps or duplicate indices. Index 0 must be the rightmost, least-significant digit. Then replace that component's explicit `digits` array with `prefix: "<display>"`. Discovery is capped at 32 digits and deliberately rejects another entity class. Perform these entity renames and the BSP rebuild manually in Hammer++; no world geometry change is required.

For a newly authored tracktrain path only: give each declared `path_track` its exact packed targetname and add an `OnPass` output targeting your trusted bootstrap `lua_run`, input `RunPassedCode`, parameter `LUASQUARE_MAP.ReportPathTrack('your_map_id','your_machine_id',CALLER)`, delay 0. This is arrival reporting, not an operator command. New physical bindings/controls require the ordinary class/targetname/output setup documented in the Control guide. VMF edits and BSP builds remain manual in Hammer++; no geometry changes are part of this migration.

DFR's map migration and its current physical-binding audit failure are deferred. Do not use DFR success/failure to mark these RBMK acceptance items complete, and do not promote `foundation-0.1`.
