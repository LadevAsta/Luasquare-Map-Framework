This is written in hierarchy.
module name (description) [progress / owner]

Architecture rule:
    luasquare_module = reusable Garry's Mod map-simulation infrastructure.
    luasquare_powerplant = reusable power/thermal/fluid plant systems.
    luasquare_dfr = Dark Fusion Reactor simulation and gameplay systems.
    bootstrapper scripts = map-repository owned; they know VMF targetnames.


luasquare_module
    +existing modules.
        3d2display.lua (3D2D operator displays, graph renderer, DISPLAYWxH_ target auto-dimensions) [existing / expanded]
        gaugedisplay.lua (Source entity gauge display driver) [existing]
        keypad_controller.lua (numeric keypad state and callbacks) [existing]
        seg7display.lua (skin-based pseudo 7-segment displays) [existing]
        annunciator/annunciator.lua (alarm annunciator lifecycle) [existing]
        rod_selector.lua (RBMK-specific enough to eventually move or rename) [existing / review later]

    logging.lua (shared logging, log history, module prefix, severity, developer print policy) [needed]
        - Should replace ad-hoc DFR.Log style later.
        - Should support loud critical errors and softer presentation warnings.

    runtime.lua (module lifecycle, central safe tick helpers, halt/error policy) [needed]
        - Owns safe pcall wrappers, critical halt behavior, timer start/stop helpers.
        - DFR, RBMK, and future map sims should not each reinvent this.

    statemachine.lua (generic named states and validated transitions) [needed]
        - DFR statecontroller should use this.
        - Useful for future startup timelines, disaster stages, and other maps.

    signalbus.lua (light event/value dispatch between modules) [needed later]
        - Named events, value updates, and optional metadata without becoming a visual node editor.
        - Useful for alarms, trips, display updates, DECAOS triggers, and debug history.
        - Typed ports can remain deferred, but the event vocabulary should become less ad-hoc.

    variables.lua (registered value definitions with units, limits, and display metadata) [needed later]
        - Documents type, unit, min/max, normal range, network/display precision, and failure behavior.
        - Helps DFR avoid hidden magic variables and helps displays show unavailable/stale data clearly.

    mapbinding.lua / sourcebinding.lua (logical map binding registry) [prototype implemented in luasquare_module/sourcebinding.lua]
        - Stores logical id, targetname, expected class, required level, notes.
        - Validates missing map entities and reports clear developer errors.
        - Later should support listening to Source outputs as well as firing Source inputs.
        - Current prototype supports first/all entity resolution for shared targetnames and Source input firing.

    controlbinding.lua (Lua-authoritative Hammer control model) [prototype implemented in luasquare_module/controlbinding.lua]
        - Defines controls, allowed states, cooldown/lock, callbacks, logical state.
        - Can fire Source inputs to lock/unlock, force press, reset, animate, or reject controls.
        - Should stay generic; DFR only registers control instances.

    machinery.lua (Hammer movable entity controller) [prototype implemented in luasquare_module/machinery.lua]
        - Controls func_tracktrain, func_rotating, func_door_rotating, func_movelinear, doors, relays.
        - Provides deploy/retract/open/close/start/stop/set speed/set position helpers.
        - Should not contain DFR-specific shaft or stabilizer names.
        - Current prototype adds path registration, destination-aware tracktrain movement, and path_track pass callbacks.

    timeline.lua (reactive timeline and sequence engine) [needed]
        - Timed events, waits, branches, cancellation, control locks, state handoff.
        - Should coordinate presentation with simulation but not replace simulation.
        - Needed later for automatic startup, DECAOS sequences, disasters, music sections.

    audiosystem.lua (map sound and music controller) [needed]
        - Plays map-wide sounds, localized sounds at targetnames, music sections, and soundscape toggles.
        - Should avoid requiring huge ambient_generic chains.
        - Should expose current music/sound state for late join sync where practical.

    subtitle.lua (networked subtitle/display text channel) [needed]
        - Generic speaker label, text, duration, priority, optional sound id.
        - DECAOS uses this, but the subtitle transport should be reusable.

    netstate.lua (small replicated state snapshots for late join and UI) [needed]
        - 3D2D already broadcasts display state, but DFR also needs subtitles, music state, timeline phase, etc.
        - Should support rate-limited server-owned state.

    cleanup.lua (cleanup/reset hooks for spawned runtime objects and temporary effects) [needed later]
        - Tracks objects created by Lua and stops dangling timers/effects when a session ends.
        - Full in-session reset can remain deferred, but cleanup ownership should be explicit.

    sourcefx.lua (generic Source presentation/effect helpers) [needed later]
        - Relays, sprites, lights, skins, bodygroups, particles/effects if practical.
        - Possible future place for prop_coreball helpers.

    profiler.lua (developer performance counters for ticks, networking, and expensive callbacks) [deferred]
        - Requirements do not need a full UI yet, but instrumentation will help once graphs, timelines, and disasters stack up.

Migration notes
    - Move generic DFR prototypes into luasquare_module:
        mapbinding.lua -> luasquare_module/mapbinding.lua or sourcebinding.lua
        control.lua -> luasquare_module/controlbinding.lua
        machinery.lua -> luasquare_module/machinery.lua
        DFR.Log parts -> luasquare_module/logging.lua
        DFR.Halt/tick safety parts -> luasquare_module/runtime.lua

    - Then shrink luasquare_dfr to actual reactor/facility/procedure code.
    - Avoid putting VMF targetnames inside reusable DFR modules.
    - Keep telemetry separate from debug.
    - Keep DECAOS-specific behavior in DFR, but subtitles/audio transport generic.


No need to touch luasquare_rbmk yet unless there has been a change in shared luasquare_module APIs.
